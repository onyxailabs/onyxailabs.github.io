How to Set Up an MCP Server: Install, Connect, Test (2026)

To set up an MCP server, you install Node.js, add one small JSON block — the mcpServers config — to your AI app, pointing it at the official filesystem server and at one folder you choose. The app then launches the server itself, and you can prove the whole thing works in the MCP Inspector: list the tools, read a real file, and watch the server refuse to touch anything outside the folder you allowed.

What MCP actually is, in plain words

MCP — the Model Context Protocol — is an open standard for connecting AI apps to tools and data. Without it, every AI assistant is sealed inside its chat window: it can talk about your files, but it cannot open one. With MCP, small programs called servers each offer a set of tools — read this file, search that database, check this calendar — and any AI app that speaks the protocol (Claude Desktop, Cursor, VS Code and others) can call those tools in a standard way. The app is the client, the server does the work, and the protocol is the shared language between them. You do not build the first server yourself; you install an official one and learn the pattern.

What you need

  • Node.js installed on your computer — it includes npx, the command that downloads and runs the server in one step. Check by running node --version in a terminal.
  • One folder you are willing to share with the AI — create a fresh practice folder with a couple of harmless text files in it. Not your whole drive, not your documents folder. One small folder, on purpose.
  • An MCP client — the Inspector below is enough for testing; afterwards the same config works in your everyday AI app.

Step 1 — The one command that runs the server

The official filesystem server is published as an npm package, and this single command runs it, with your chosen folder as its argument:

npx -y @modelcontextprotocol/server-filesystem /path/to/your/folder

The -y simply answers "yes" to the first-run download prompt. Notice what the command really says: run this server, and this folder is its whole world. You do not need to memorise the command — you will not type it each time — because the config in the next step stores it permanently. But understanding it matters: every MCP setup, however fancy, is ultimately a command like this one, launched by the client.

Step 2 — Write the mcpServers JSON config

Every MCP client reads the same shape of configuration. Inside your AI app's settings or config file, you add a block like this:

The config block (copy the shape, change the path)

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/your/folder"]
    }
  }
}

Three ideas carry the whole system: the name ("filesystem" — your label), the command that launches the server, and the args, where the last entry is the folder the server may touch. In Claude Desktop this block lives in a file called claude_desktop_config.json; other clients keep it in their MCP settings screen — the contents are identical.

Restart the client after saving. On startup it launches the server silently in the background, asks it what tools it offers, and makes those tools available to the AI. If the server fails to appear, the cause is almost always in this block — a wrong folder path or a JSON slip such as a missing comma — so check it character by character before suspecting anything grander.

Step 3 — Connect in the MCP Inspector and see the tools

Before trusting the setup inside a chat app, test it in the open with the official testing tool. Run npx @modelcontextprotocol/inspector, and the Inspector opens in your browser. Enter the same command and arguments from your config — the filesystem server and your folder — and click Connect. Then open the Tools tab and choose List Tools.

You should see the server's full toolbox laid out — fourteen tools in the current official build, including list_directory, read_text_file, read_multiple_files, search_files, write_file and edit_file, plus directory and file-info helpers. This list is the honest answer to "what can this server do?" — nothing more, nothing hidden. An AI connected to this server can call exactly these tools, on exactly your allowed folder.

Step 4 — Run real tool calls: list, then read

Still in the Inspector, select list_directory, enter your folder's path, and run it. The result is the folder's real contents, returned by the server — proof the chain works from client, to server, to disk. Then select read_text_file, point it at one of your practice text files, and run it: the file's actual contents come back. These two calls are the heartbeat of every filesystem workflow — the AI first sees what exists, then reads what it needs, instead of guessing.

Now the most instructive test of all: try to read a file that is outside your allowed folder — a system file, for example. The server refuses with an access error. That refusal is not a bug; it is the entire safety model working in front of you.

The allowed-directory boundary — the part that keeps you safe

An MCP filesystem server can only see the directories named in its arguments. It cannot wander your drive, because paths outside the boundary are rejected before any reading happens. This makes your one real decision simple and serious: choose the smallest folder that makes the tool useful. A project folder, yes. Your entire home directory, no. Remember too that this server's toolbox includes writing and editing files, not just reading — inside the boundary, the AI can change things. Start with a practice folder, watch what the tools do, and widen access only when you understand what you are granting. The same discipline appears in our YouTube API key guide: small permissions, granted on purpose, beat broad access granted casually.

Honest limits — what to watch out for

  • The server runs only while the client runs. These local (stdio) servers are launched by your AI app on your machine and stop when it closes. They are personal tools, not always-on cloud services.
  • Config mistakes cause nearly every failure. Wrong paths, Windows-style versus Mac-style path formats, and JSON punctuation errors account for almost all "it doesn't work" reports. Recheck the block before reinstalling anything.
  • Not every server deserves trust. A server is a program running on your computer with the permissions you gave it. Prefer official and well-known servers, and read a community server's tool list in the Inspector before connecting it to anything real.
  • Connection is not competence. MCP gives the AI hands; it does not give it judgement. Review what it writes or changes, especially early on.

Frequently asked questions

Is MCP free to use?

Yes. The protocol is an open standard, the official filesystem server is free, and the Inspector is free. Costs only enter the picture if you later choose paid servers, paid AI apps or hosted infrastructure — the setup in this guide uses none of them.

Is it safe to let an AI read my files?

It is as safe as the boundary you set. The server can only reach the folders in its arguments, and outside paths are refused — which you proved yourself in Step 4. Keep the boundary small, start with harmless files, and remember the toolbox includes writing tools, so treat real folders with the same care you would give any powerful utility.

How is MCP different from a plugin or an API key?

An API key authorises calls to one company's service. MCP is a shared language that lets many different tools — files, databases, calendars, the web — plug into many different AI apps the same way. One protocol, many servers, instead of a separate integration for every pair.
